## Overview

SGCC는 Sogang Computer Club의 약자로, 1982년에 만들어진 서강대학교 중앙 컴퓨터 동아리입니다. 방학 동안 동아리 사람들과 함께 동아리 공식 웹사이트를 새로 만들었습니다. 일주일에 한 번씩 동아리방에 모여 작업을 이어 갔습니다.

동아리 소개와 모집, 일정, 스터디, 활동 기록이 흩어져 있던 것을 하나의 사이트로 모으고, 처음 동아리를 알아보는 신입생도 휴대폰으로 편하게 둘러볼 수 있게 하는 것이 목표였습니다.

현재 실제 사이트는 운영이 끝났습니다. 당시 코드를 정적 페이지로 다시 빌드해 [이 포트폴리오 안에서 직접 둘러볼 수 있게](/demos/sgcc/) 했습니다. 일정 달력은 비워 두었고, 피드·미디어관의 글은 개발 중에 쓴 예시 데이터입니다. 아래는 설계한 화면입니다.

## Front-end

프론트엔드 페이지 구현을 맡았습니다. SvelteKit(Svelte 5)과 TypeScript, Tailwind CSS로 데스크톱과 모바일을 함께 맞췄습니다.

- **반응형** — 데스크톱과 모바일의 화면 구성을 따로 설계하고, 같은 내용이 휴대폰에서는 다른 배치로 보이게 했습니다. 모바일에서는 메뉴를 열면 뒤 화면이 스크롤되지 않게 막고, 피드는 모바일 전용 카드로 바꿔 보여 줍니다.
- **일정 달력** — 동아리 일정을 달력에 띄우고, 여러 날에 걸친 일정을 이어서 보여 주며, 월·연도를 넘겨 볼 수 있게 했습니다.
- **공통 컴포넌트** — 헤더·내비게이션, 모바일 메뉴, 이미지 슬라이더, 페이지 제목, 피드 카드처럼 여러 페이지에서 쓰는 부분을 컴포넌트로 나눠 일관되게 만들었습니다.
- **동아리다운 분위기** — 검은 바탕에 네온 느낌의 글자, 서강대학교 전용 서체와 Pretendard를 함께 써서 컴퓨터 동아리의 분위기를 냈습니다.

2025년 9월 자체 도메인을 연결해 실제로 배포했습니다.

## Study

프로젝트를 시작할 당시에는 웹을 제대로 만들어 본 경험이 거의 없어, 디자인 도구와 개발 환경을 익히는 것부터 시작해야 했습니다.

- **피그마** — 처음에는 컴포넌트와 오토 레이아웃을 활용할 줄 몰라 같은 버튼과 메뉴를 페이지마다 따로 만들었습니다. 하나의 요소를 수정해도 모든 화면을 다시 손봐야 했습니다. 방학 동안 Figma 강의를 들으며 컴포넌트와 오토 레이아웃을 익혔고, 이후에는 헤더·메뉴·카드와 같은 공통 요소를 한 번 만들어 여러 화면에서 재사용할 수 있게 되었습니다.
- **SvelteKit과 Tailwind CSS** — Figma에서 설계한 화면을 실제 웹으로 구현하는 과정은 생각보다 어려웠습니다. 디자인에서 맞춰 둔 간격과 글자 크기가 브라우저에서는 다르게 보였고, 화면 크기에 따라 레이아웃이 깨지기도 했습니다. 다양한 화면 크기에서 결과를 확인하고 수정하며 반응형 웹을 구현하는 방법을 익혔습니다. 반복되는 화면 요소는 컴포넌트로 분리해 관리할 수 있게 되었습니다.
- **협업** — 디스코드로 의견을 나누거나 동아리방에 모여 화면 구성과 콘텐츠 배치를 함께 고민하면서 시각적으로 보기 좋은 디자인이 반드시 구현하기 쉽거나 사용하기 편한 것은 아니라는 점을 알게 되었습니다. 디자인과 실제 구현 가능성, 사용자가 정보를 이해하는 방식까지 함께 고려하며 UI를 설계해야 했습니다. 또한 여러 화면에서 공통으로 사용할 요소를 먼저 정해 일관성을 유지하고자 했습니다.

프론트엔드를 공부하면서 화면 뒤에서 데이터가 처리되는 백엔드에도 관심이 생겼습니다. 『점프 투 FastAPI』를 읽으며 웹페이지를 처음부터 직접 만들어 보았습니다. 책을 따라 FastAPI로 서버를 구축하고, 데이터베이스에 글을 저장하고 불러오는 API를 만들어 화면과 연결했습니다. 이를 통해 화면에서 보낸 요청이 서버에서 처리되고, 데이터베이스와 연동된 결과가 다시 화면에 전달되는 흐름을 직접 경험했습니다. SGCC에서는 프론트엔드를 담당했지만, 별도로 백엔드까지 공부한 덕분에 웹서비스가 화면만으로 작동하는 것이 아니라 여러 요소가 연결되어 구현된다는 점을 이해할 수 있었습니다.
