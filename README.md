## 1. 폴더 구조

Google Drive의 `포트폴리오_자료/` 구조를 그대로 옮겼습니다.

```
works/                         ← 모든 작업 (Drive의 포트폴리오_자료/)
├── 01_SERVICE/                ← 카테고리 폴더: "번호_이름"
│   ├── _category.md           ← 카테고리 한 줄 설명 (선택)
│   ├── 손길/
│   │   ├── index.md           ← 이 작업의 글 + 설정  ★ 이 파일만 고치면 됩니다
│   │   ├── cover.jpg          ← 대표 이미지 (이 이름이면 자동으로 표지가 됩니다)
│   │   ├── 01.jpg, 02.jpg …   ← 상세 이미지
│   │   └── 기획서.pdf          ← PDF, 발표 자료
│   ├── 쓰레개똥/
│   ├── SGCC/
│   └── 대집마련/
├── 02_MEDIA/      (AI영상, AI음악)
├── 03_DATA/
│   ├── PARROT/                ← 하위 프로젝트가 있는 "묶음" 작업
│   │   ├── index.md
│   │   ├── 데이터톤_26-1/index.md
│   │   ├── 데이터톤_26-2/index.md
│   │   ├── 반도체/ · 드론/ · 로봇팔/ · ML/ · DL/ · 홈커밍데이/
│   ├── AIFA/
│   └── SogangIntelligence/    (논문스터디, 카드뉴스, S2H)
└── 04_EXHIBITION/ (미엔날레, 전후자서포터즈, AI동시 전시)

content/
├── site.md        ← 이름, 소개 문구, 이메일, SNS 링크 (사이트 전체)
├── about.md       ← ABOUT 페이지
└── files/         ← 이력서 등 공용 파일 (예: files/resume.pdf → 주소 /files/resume.pdf)

src/assets/        ← 디자인(CSS)과 움직임(JS). 디자인을 바꿀 때만 엽니다.
scripts/           ← 웹사이트를 만들어 주는 프로그램. 고칠 일 거의 없음.
```

- 폴더 이름은 **한글, 띄어쓰기 모두 괜찮습니다.** (Drive와 똑같이 써도 돼요)
- 이름이 `_` 나 `.` 으로 시작하는 폴더는 사이트에 나오지 않습니다. 작업 중인 자료는 `_보관/` 같은 폴더에 두세요.
- `00_웹사이트_자료정리`(구글 시트)는 정리용이라 저장소에 넣지 않았습니다.

## 2. 자주 하는 일

### 사진 올리기 (GitHub 웹사이트에서)

1. 저장소에서 `works` → 원하는 작업 폴더(예: `01_SERVICE/손길`)로 들어가기
2. 오른쪽 위 **Add file → Upload files** → 사진을 끌어다 놓기
3. 아래 **Commit changes** 누르기

이것만 해도 사진이 사이트에 나옵니다. `index.md`에 따로 적지 않은 사진은
**파일 이름 순서대로** 작업 페이지 맨 아래에 자동으로 배치됩니다 (1장 → 2장 → 1장 → 2장 리듬).
순서를 바꾸고 싶으면 파일 이름을 `01.jpg`, `02.jpg` … 처럼 바꾸면 돼요.

> 자리, 크기, 순서를 직접 정하고 싶다면 → 아래 **4. 본문에 사진·영상 배치하기**

### 대표 이미지(표지) 바꾸기

- 폴더 안의 `cover.jpg`(또는 `.png`, `.webp`, `.gif`)를 바꿔서 올리면 끝.
- 다른 파일을 표지로 쓰려면 `index.md` 머리말에 `cover: 03.jpg`
- 유튜브 썸네일을 표지로: `cover: https://youtu.be/영상ID` (작업 페이지 맨 위에서는 재생도 됩니다)
- 표지가 없으면 본문의 첫 이미지 → 그것도 없으면 점 무늬 "이미지 자리"가 보입니다.
- HOME의 SELECTED WORKS(`featured: true`)에서는 표지가 3D 큐브에 붙었다가 펼쳐집니다. 이때 표지는 **정사각형으로 잘려** 보이니, 중요한 부분이 가운데 오는 사진이 잘 어울려요. (모바일에서는 일반 카드)

### 글 고치기

`index.md` 파일을 열고 연필 아이콘(✏️ Edit)을 누르면 웹에서 바로 고칠 수 있습니다.
다 고친 뒤 **Commit changes**.

### 새 작업 추가하기

1. 카테고리 폴더 안에 새 폴더 만들기
   (GitHub 웹: **Add file → Create new file** 에서 이름 칸에 `works/01_SERVICE/새작업/index.md` 라고 쓰면 폴더도 같이 생겨요)
2. 아래 **3. index.md 쓰는 법**의 틀을 복사해서 채우기
3. 사진은 같은 폴더에 올리기

코드를 고칠 필요는 없습니다. 메뉴, 목록, 카테고리 개수, 이전/다음 링크가 모두 자동으로 바뀝니다.

### 하위 프로젝트 추가하기 (PARROT처럼)

작업 폴더 안에 폴더를 하나 더 만들고 `index.md`를 넣으면, 그 작업 페이지 아래 **PROJECTS** 목록에 자동으로 붙습니다.

### 새 카테고리 추가하기

`works/05_RESEARCH/` 처럼 `번호_이름` 폴더를 만들면 됩니다. 번호 순서대로 정렬됩니다.
한국어 설명은 그 폴더에 `_category.md`를 만들고:

```
---
title_ko: 연구 및 논문
---
카테고리 페이지에 보일 한두 문장 설명.
```

## 3. index.md 쓰는 법

파일 맨 위 `---` 사이가 **머리말(설정)**, 그 아래가 **본문**입니다.

```markdown
---
title: 손길
title_en: Sonkil — Remote Sign Language Counseling
slug: sonkil
year: 2026
period: 2026.03 – 2026.06
role: 팀장 (기획, 데이터 전처리, 웹 구현)
team: 4명
tools: Figma, Python, React
summary: 청각장애인을 위한 비대면 수어 상담 서비스.
status: 진행 중
featured: true
order: 1
info:
  - 수상 | 서강대 해커톤 장려상
links:
  - GitHub | https://github.com/JUEHEE/...
  - 발표 자료 PDF | 발표자료.pdf
  - 시연 영상 | https://youtu.be/...
---

## 배경

본문은 여기부터 자유롭게 씁니다.
```

| 항목 | 뜻 | 꼭? |
|---|---|---|
| `title` | 작업 이름 | ✔ |
| `title_en` | 영문 이름 / 부제 | |
| `slug` | 웹 주소에 쓰일 영문 이름 → `juehee.github.io/works/sonkil/` (한 번 정하면 바꾸지 않기) | 권장 |
| `year` | 연도 (정렬과 목록에 쓰임) | 권장 |
| `period` `role` `team` `tools` | 상세 페이지 오른쪽 정보표 | |
| `info` | 정보표에 더 넣을 줄. `- 라벨 \| 내용` | |
| `summary` | 한두 문장 소개 (카드, 검색엔진 설명) | 권장 |
| `status` | `진행 중` 같은 작은 표시 | |
| `featured` | `true` 면 HOME의 SELECTED WORKS에 나옴 | |
| `order` | 같은 카테고리 안에서의 순서 (작을수록 앞) | |
| `cover` | 표지 파일 이름 또는 유튜브 주소 | |
| `card` | 목록에서 카드 크기: `large` / `wide` / `small` | |
| `links` | 버튼 링크. `- 라벨 \| 주소`. 주소에 PDF 파일 이름만 쓰면 같은 폴더의 파일로 연결. 주소를 비워 두면 "링크 필요"로 표시 | |
| `hero` | `false` 면 상세 페이지 맨 위 큰 표지를 숨김 | |
| `auto_gallery` | `false` 면 본문에 안 쓴 사진을 자동으로 붙이지 않음 | |
| `draft` | `true` 면 사이트에 나오지 않음 (작성 중일 때) | |

**본문은 정해진 틀이 없습니다.** 배경, 문제 정의, 과정, 역할, 결과… 작업마다 필요한 제목만 `## 제목`으로 쓰면
왼쪽에 작은 제목, 오른쪽에 본문이 놓이는 편집 레이아웃으로 바뀝니다.

| 쓰는 법 | 결과 |
|---|---|
| `## 과정` | 섹션 제목 |
| `### 작은 제목` | 본문 안 작은 제목 |
| `**굵게**`, `*기울임*` | 굵게, 기울임 |
| `[GitHub](https://github.com/...)` | 링크 |
| `- 항목` / `1. 항목` | 목록 |
| `> 한 문장` | 크게 강조된 인용문 |
| `---` | 얇은 구분선 |
| `[작성 필요]` | 주황색으로 표시 (채우는 걸 잊지 않게) |

## 4. 본문에 사진·영상 배치하기

한 줄에 하나씩, 이렇게 씁니다:

```markdown
![캡션](파일이름 "옵션")
```

```markdown
![첫 화면 시안](01.jpg)                         ← 기본: 넓게
![현장 사진](02.jpg "full")                      ← 화면 끝까지 꽉
![스케치](03.jpg "medium right")                 ← 중간 크기, 오른쪽
![작은 메모](04.jpg "small left")                ← 작게, 왼쪽

![A안](05.jpg)                                   ← 빈 줄 없이 붙여 쓰면
![B안](06.jpg)                                   ← 한 줄에 나란히!
![C안](07.jpg)                                   ← (비율이 달라도 높이를 맞춰 줍니다)

![시연 영상](https://youtu.be/AbC123xyz)         ← 유튜브: 썸네일 → 누르면 재생
![쇼츠](https://youtube.com/shorts/AbC123xyz)    ← 세로 영상은 자동으로 세로
![티저](https://youtu.be/AbC123xyz "thumb")      ← 썸네일만 (누르면 유튜브로 이동)
![짧은 루프](loop.mp4 "loop")                    ← 소리 없이 반복 재생 (GIF처럼)
![기획서](기획서.pdf)                            ← PDF는 문서 링크 줄로 표시
```

| 옵션 | 뜻 |
|---|---|
| `full` | 화면 너비 가득 |
| `wide` | 넓게 (기본값) |
| `medium` | 중간 |
| `small` | 작게 |
| `left` / `right` | `medium`, `small`과 함께 써서 왼쪽/오른쪽으로 비대칭 배치 |
| `ratio=4:5` | 아직 파일이 없을 때 "이미지 자리"의 비율 |
| `thumb` | 유튜브를 사이트 안에서 재생하지 않고 썸네일만 |
| `loop` | 영상을 자동, 무음, 반복 재생 |

- 옵션은 띄어쓰기로 여러 개: `"medium left"`
- 캡션을 비우면 캡션 없이: `![](01.jpg)`
- 사진과 글을 번갈아 쓰면 그 순서대로 배치됩니다.

## 5. 사진과 영상 규칙

| 자료 | 어디에 | 규칙 |
|---|---|---|
| 사진 | 작업 폴더 | JPG/PNG/WebP/GIF. 긴 쪽 **2000px 이하**, 한 장 **5MB 이하** 권장. 비율은 자유 (세로, 가로, 정사각 모두 OK) |
| 영상 | **유튜브** (일부 공개도 가능) | 저장소에 큰 영상 넣지 않기 (GitHub은 100MB 넘는 파일을 거부합니다). 몇 초짜리 루프 영상(10MB 이하)만 `mp4`로 폴더에 |
| PDF, 발표 자료 | 작업 폴더 | 20MB 이하 권장 |
| 이력서 | `content/files/resume.pdf` | 주소: `/files/resume.pdf` |

- 사이트가 만들어질 때 사진은 자동으로 여러 크기의 WebP로 줄어들고(휴대폰에선 작은 사진을 받음),
  화면에 보일 때만 불러옵니다(Lazy Loading). 원본은 그대로 남습니다.
- 휴대폰 사진의 회전 정보도 반영되니 세로 사진이 눕지 않습니다.
- 위치 정보(GPS)가 들어 있는 원본 사진은 올리기 전에 지우는 것을 권장합니다
  (아이폰: 공유 → 옵션 → 위치 끄기).
- 파일이 너무 크면 Actions 기록에 `!` 경고가 나옵니다.

## 6. 사이트 전체 정보 바꾸기

`content/site.md`에서 이름, 첫 화면 문구, POIESIS 설명, 이메일, SNS를 바꿉니다.

```
email: hello@example.com
links:
  - GitHub | https://github.com/JUEHEE
  - Instagram | https://www.instagram.com/olive0kk
  - LinkedIn | https://www.linkedin.com/in/...
```

ABOUT 페이지는 `content/about.md` (작업 페이지와 같은 문법). 프로필 사진은 `content/`에 넣고 `portrait: 파일이름`.

색과 글꼴은 `src/assets/css/style.css` 맨 위 `:root` 의 값만 바꾸면 전체에 반영됩니다.

(미리보기에서는 이미지 WebP 변환이 생략될 수 있어요. 실제 사이트에서는 자동으로 됩니다.)

## 8. 어떻게 동작하나요? (궁금할 때만)

```
works/ + content/  ──(GitHub Actions가 scripts/build.mjs 실행)──▶  완성된 HTML  ──▶  juehee.github.io
```

- **정적 사이트 생성기**: 마크다운 파일을 읽어 페이지마다 완성된 HTML을 미리 만들어 둡니다.
  그래서 빠르고, 검색엔진이 내용을 잘 읽고(SEO), 자바스크립트가 꺼져 있어도 내용이 보입니다.
- 별도 프레임워크나 데이터베이스가 없습니다. 외부 패키지는 이미지 최적화용 `sharp` 하나이며, 없어도 빌드됩니다.
- 사이트맵(`sitemap.xml`), 공유 미리보기(Open Graph), 접근성(키보드 이동, 대체 텍스트, 움직임 줄이기 설정)을 지원합니다.
- 만들어진 결과(`_site/`)는 저장소에 올리지 않습니다. Actions가 매번 새로 만듭니다.

### 보안 메모

- 이 사이트에는 API 키, 비밀번호, 서버가 없습니다. 저장소는 공개(public)이므로
  **올린 파일은 누구나 볼 수 있다**는 점만 기억하세요 (주민번호, 전화번호, 주소가 담긴 PDF 주의).
- 공개하고 싶지 않은 이메일은 `site.md`에 적지 마세요.
